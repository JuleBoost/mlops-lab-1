Lab 2 - Answers

1. pyproject.toml vs uv.lock?
pyproject got mlflow, sklearn, torch, torchvision + CUDA index/sources for GPU wheels.
uv.lock 101 -> 180 pkgs (numpy, pandas, scipy, sqlalchemy, flask, etc., mostly via mlflow).
pyproject = hand-written ranges; uv.lock = exact pinned versions/hashes for reproducible sync.

2. backend-store-uri vs default-artifact-root?
backend (sqlite:///mlflow.db): structured metadata (experiments, runs, params, metrics, tags) for tables/charts.
artifact-root (./mlruns): output files (weights, plots). Metadata = small queryable rows; artifacts = large blobs on disk.

3. Why ignore mlflow.db + mlruns/ in git and dvc?
git: db is binary changing every run (no diff, bloat); mlruns holds large weights.
dvc: dvc = versioned inputs (data). These are local changing outputs; runs already live in tracking server. git=code, dvc=data, mlflow=runs.

4. First set_experiment("food11")?
Creates it (id 1, next to Default id 0), artifact loc ./mlruns/1. Later calls just reuse it.

5. log_param vs log_metric + step?
param = fixed input (lr, batch_size), logged once. metric = evolving output (loss, accuracy), series over time; step=epoch positions each point for charts.

6. Where is model on disk?
mlruns/1/models/<m-id>/artifacts/ with data/model.pth (~43MB) + MLmodel, requirements.txt, conda.yaml, python_env.yaml. Params/metrics shown from mlflow.db, model is file DB points to.

7. Best lr? Higher better?
lr=0.0001 wins: 0.7609 val / 0.8184 test vs 0.5684 (0.001) vs 0.1788 (0.01). No, higher is worse here; 0.01 (~random 0.09 for 11 classes) diverges, small steps preserve pretrained resnet18.

8. Parallel coords pattern?
lr decides, batch_size ~nothing. Bands 0.76/0.57/0.18 by lr; at lr=0.001 batch 32=0.5684 vs 64=0.5703. Tune lr.

merciful-mink-416, a6e7d48d7d2441299c60f28a3ca4b6f4 (mini, lr 0.0001, bs 32, 5ep, val 0.7609, test 0.8184, lowest val_loss 0.71).
